#匹配恶意流量——Yara规则
2025-07-22

前置知识确保了解正则表达式。

文献参考于Detection of Malware by Using YARA Rules.

Yara基本规则：meta，strings，condition。

meta：可选，通常用于存储与规则相关的元信息，如规则的描述、作者、创建日期等。

strings：定义了需要匹配的字符串模式。

condition：定义了触发规则的条件。Yara会根据此条件在文件或内存中查找模式。

demo样式：

Rule<name>:the name of the rule

Meta:Description of the rule like data created, author etc,

String:The actual value/strings which we want to search.This could be Hex,String or Regex.

Condition:The entire logic of the rule.

简单用例：

//这条规则判断a和b字符串出现的次数，
//例如，#a语法用于表示$a在目标文件或数据中出现的次数
rule Count
{
    strings：
      $a = "javon"
      $b = "cs466"
    condition:
      #a == 6 or #b > 10 
}

//这条规则用来判断文件大小是否大于25KB
rule FileSize
{
  condition:
    filesize > 25KB
}

//这条规则用来判断目标文件或者数据中至少满足三个字符串
//例如，&a语法用于引用$a
//例如，of用于检查字符串满足条件的数量
rule SetStrings
{
  strings:
    $a = "cs466"
    $b = "is"
    $c = "awesome"
    $d = "not"
   condition:
     3 of (&a,&b,&c, &d)
}

//这条规则用来匹配字符串,十六进制的字符串,UTF-8编码的unicode字符以及正则表达式
rule HexString
{
  strings:
    $my_text_string = "some text can be here"
    $my_hex_string = { 74 68 69 73 20 69 73 20 6E 6F 74 20 61
    20 76 69 72 75 73 }
    
  condition:
    $my_text_string or $my_hex_string
}

//这条规则用来排除已知的良性模式，减少误报
rule Exclude
{
  strings:
    ·······
  
  condition:
    &str1 and not $good_str
}

灵活性和复杂性提升：

//匹配复杂模式
  strings:
    $regex1 = /cmd\.exe\s+/i

//模糊匹配
  strings:
    $regx2 = /malware_[A-Za-z0-9]{5}/
    
//捕获组和前后文
  strings:
    $regex3 = /User\s+Agent:\s+Mozilla\/\d+\.\d+/

//结合其他字符串
  condition:
    $str1 and $regex1
    
//逻辑运算符:and、or、not
  condition:
    $str1 and ($str2 or %str3)
    
//算术运算
  condition:
    filesize > 1MB and $str1
    
//计数和数量：使用#符号对字符串出现的次数进行判断
  condition:
    #strings > 5
    
//范围和位置：使用of、in等关键字限制字符串出现的范围和位置
  condition:
    any of ($a,$b,$c) and unit16(0) == 0x5A4D
    
//集合和列表：all of、any of、none of集合运算，用于字符串列表
  condition:
    all od them

//函数和内置操作：使用内置函数和操作符
  condition:
    pe.is_exe and filesize < 5MB and $str1

实际用例：

//这条规则用于检测特定的HTTP请求
//例如，$header at 0确保请求方法出现在请求的开头
//例如，$str* 确保请求中至少包含str1或str2字符串
rule test
{
  meta:
    ........
  strings:
    $header = /(GET|POST)/
    $url = "/u8cloud/openapi/uapbd.refdef.query"
    $stt = /\"refName\"\:[\S\s]{1,40}(DELAY|select|union|sleep|from|and|concat|sqlvarbasetostr)/ nocase
    $str1 = /appcode=[a-zA-Z0-9]+/
    $str2 = /isEncrypt=[a-zA-Z0-9]+/
  condition:
    $header at 0 and $url and (1 of ($str*)) and $stt
}

在$stt中，正则小课堂：

  • \"refName\"\：匹配json字段refName及其冒号。
  • [\S\s]{1,40}：匹配1到40个任意字符串（包括空白字符和非空白字符）。
  • (DELAY|select|union|sleep|from|and|concat|sqlvarbasetostr)：匹配以上SQL注入关键字之一。
  • nocase：不区分大小写，即匹配时不考虑大小写。

扩展的Yara规则

例如，检查PE文件的其他特征，如魔法数、文件大小、节表和导入表等。

rule ExtendedExampleRule {
    meta:
    ·······
    
    condition:
        // 检查PE文件的魔数

        // 检查PE文件的签名

        // 检查文件大小

}

类似规则还有Nuclei模板

Nuclei 主要用于自动化漏洞扫描和 Web 应用安全检查，而 YARA-Gen 主要用于自动生成 YARA 规则，检测恶意软件样本；

基本原理：Nuclei 通过发送 HTTP/HTTPS 请求到目标系统，并根据预定义的模板检查响应，以检测特定的漏洞或安全问题。Nuclei 的核心是模板，每个模板定义了一个特定的检查逻辑。

demo示例：

id: example-http-response-check

info:
  name: Example HTTP Response Check
  author: John Doe
  severity: medium
  description: Detects a specific string in the HTTP response
  reference:
    - https://example.com/vulnerability
  tags: http,response,example

requests:
  - method: GET
    path:
      - "{{BaseURL}}/vulnerable-page"

    matchers-condition: and
    matchers:
      - type: word
        part: body
        words:
          - "vulnerable_string_1"
          - "vulnerable_string_2"
        condition: or

      - type: status
        status:
          - 200
  1. ID：模板的唯一标识符；
  2. Info：包含模板的元数据，如名称、作者、描述、分类等
  3. Requests：定义HTTP请求和响应处理逻辑
  4. Matchers：定义匹配条件，用于检测漏洞或安全问题
